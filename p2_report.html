요  약

자동 핵산추출 장비의 머신비전이 시약 표면의 빛반사를 well 경계선으로 오인하여 6-well 카트리지를 8-well 카트리지로 오인식하는 문제가 실제 현장에서 발생했다. 이러한 오인식을 유발하는 빛반사를 학습·검출하려면 충분한 양의 반사 이미지와 정답(GT) 라벨이 필요하나, 실제 현장 이슈 사진은 2장에 불과했고 물로 빛반사를 재현·촬영한 사진 5장을 더해도 학습 데이터로 활용하기에는 절대적으로 부족했다. 본 보고서는 결함이 없는 정상 카트리지 사진 1장으로부터 사실적인 빛반사 결함 이미지와 GT bbox 라벨을 자동 합성하는 데스크톱 애플리케이션의 설계와 구현을 기술한다. 시스템은 렌즈 왜곡(fisheye)을 파라미터로 기술하는 파라메트릭 well 그리드로 합성 위치를 정합하고, 실물 사진에서 추출한 반사 패치를 코어(specular core)만 남도록 정규화한 뒤, 불투명 붙여넣기가 아닌 screen 블렌딩으로 "빛을 더하는" 방식으로 합성한다. 패치는 모양 필터(장단비·채움률)를 통과한 streak형만 사용하며(844 → 213), 결함 강도는 L1~L5의 5단계로 개수·크기·밝기·액면 강도에 수치 매핑된다. 합성 위치를 시스템이 알고 있으므로 GT bbox 라벨은 수작업 없이 100% 자동 생성된다. 합성 품질은 실물 레퍼런스와의 대조를 기준으로 조정하였으며, 미리보기와 배치 생성이 동일 엔진을 경유하도록 설계하여 "보이는 것 = 출력되는 것"을 보장하였다. 정상 사진 1장으로부터 1,000장 이상의 학습 이미지 배치 생성을 확인하였으며, 이렇게 양산된 데이터는 결함 이미지를 일일이 촬영하지 않고도 장비 머신비전의 인식 성능을 최적화하는 학습 재료가 된다.

주제어: 합성 데이터(synthetic data), 머신비전, 빛반사 결함, GT 라벨 자동 생성, 파라메트릭 기하 모델링, screen 블렌딩, OpenCV

1. 서론

1.1 배경 및 문제 정의

자동 핵산추출 장비의 머신비전은 장착된 시약 카트리지를 촬영하여 카트리지의 종류를 인식한다. 그런데 시약 표면의 빛반사(specular reflection)가 well 경계선과 유사한 줄무늬로 나타나면서, 실제 현장에서 6-well 카트리지에 줄이 하나 더 있는 것으로 해석되어 8-well 카트리지로 오인식되는 문제가 발생했다. 이러한 오인식 유발 빛반사를 학습 모델로 검출·구분하려면 다량의 반사 이미지와 각 반사의 위치를 표기한 GT(ground truth) 라벨이 필요하다. 그러나 해당 현상은 발생 빈도가 낮아 실제 현장에서 발생한 이슈 사진은 2장에 불과했고, 시약 대신 물을 채워 빛반사를 재현·촬영한 사진 5장가량을 더해도 검출 모델 학습에는 절대적으로 부족한 양이었다. 문제가 재발하기를 기다려 데이터를 모으는 접근은 시간이 오래 걸릴 뿐 아니라 라벨링 수작업 비용도 수반한다. 본 보고서에서 "결함 이미지"는 이러한 오인식을 유발하는 빛반사가 포함된 카트리지 이미지를 지칭하며, 본 시스템은 이를 자동 양산하는 프로그램이다.

1.2 접근 및 범위

본 개발은 "데이터가 없다"를 결론이 아니라 다음 문제의 정의로 보고, 결함 데이터를 직접 생성하는 도구를 구현하는 접근을 취했다. 합성의 입력(베이스)은 결함이 없는 빈 시약 카트리지 사진이며, 확보된 소량의 실물 사진 — 실제 현장에서 발생한 이슈 사진 2장과 물을 활용해 빛반사를 재현·촬영한 사진 5장가량 — 은 학습 데이터가 아니라 합성의 재료(반사 패치 추출원)와 사실성 판단의 레퍼런스로만 사용한다. 산출물은 결함이 합성된 학습 이미지와 이미지별 GT JSON(레벨, 시드, 엔진 버전, well 단위 bbox·강도)이다. 이렇게 양산된 결함 이미지를 머신러닝 학습에 투입하면 오류 이미지 데이터가 축적되면서, 결함 상황을 일일이 촬영하지 않고도 장비 머신비전의 인식 성능을 최적화(오인식 재발 방지)할 수 있다. 합성 품질은 정답이 고정된 문제가 아니라 실물 레퍼런스에 지속적으로 수렴시켜 가는 과제로 정의하였다.

2. 설계 원칙

본 시스템은 다음 세 원칙을 설계 기준으로 삼았다.

  1. 빛을 더하는 합성 — 반사는 물체가 아니라 빛이다. 불투명 패치 붙여넣기는 well 바닥의 액체 텍스처를 가려 부자연스러우므로, 바닥을 살리면서 밝기만 더하는 screen 블렌딩을 사용한다.
  2. 재료부터 검증 — 패치 라이브러리의 품질이 곧 합성 사실성의 상한이다. 패치 모양 자체를 수치(장단비·채움률)로 검사하여 실물과 다른 둥근 blob형을 라이브러리 진입 단계에서 차단한다.
  3. 미리보기 = 실제 출력 — 미리보기와 배치 생성이 동일한 엔진·마스크 경로를 경유하도록 하여, 사용자가 확인한 화면과 실제 산출물이 달라질 가능성을 구조적으로 제거한다.

3. 시스템 설계

3.1 전체 구조

시스템은 customtkinter 기반 데스크톱 GUI로, 3단계 위저드 흐름(Setup → Generate → Progress)을 가진다. 사용자는 빈 카트리지 사진을 선택해 well 그리드(마스크)를 정합·저장하고, 총량과 레벨 분포를 설정한 뒤 배치 합성을 실행한다.

4. 파라메트릭 마스크 시스템

4.1 fisheye 곡면의 파라미터화

카메라 렌즈 특성상 카트리지 배열은 평면 격자가 아닌 곡면으로 촬영된다. 반사를 "어디에" 심는지가 사실성의 절반이므로, 그리드를 다음 파라미터로 수식화하여 well 하나하나에 좌표를 정합한다. 그리드는 24열 × 앞 3행(최대 72칸)이며 표준 설정(edge_skip=4)에서 48 well을 대상으로 한다.

4.2 마스크 영속화

정합된 마스크(mask_config.json)는 이미지의 SHA-256 해시를 키로 문서 폴더에 저장되어, 같은 사진이면 재실행·재빌드 후에도 자동 복원된다. 합성된 반사는 well 폴리곤 내부로 컨테인되므로 경계를 벗어난 비현실적 합성이 구조적으로 발생하지 않는다.

5. 합성 방법

5.1 패치 라이브러리 — 2소스 수집과 동일 정규화

반사의 씨앗이 되는 패치는 두 소스에서 수집한다: 실물 사진(현장 이슈 2장 + 물 재현 5장가량)에서 추출한 real 패치 21개와 생성형 AI로 만든 synthetic 패치이다. 두 소스는 동일한 파이프라인으로 정규화된다 — grayscale 변환, 국소 배경 차감, 높은 임계값 적용으로 specular 코어만 남기고 중간 회색 halo는 폐기한다(블러 없음).

5.2 모양 필터 — blob 차단

실물 반사는 가는 streak(줄무늬) 형태인 반면, AI 생성 패치의 다수는 둥근 blob 형태였다. 패치의 최소외접사각형 장단비(elongation ≥ 2.2)와 solidity(볼록 껍질 대비 면적비 ≤ 0.72 — 둥글게 꽉 찬 형태일수록 1에 가까움)를 검사하여 streak형만 라이브러리에 진입시킨다. 이 필터로 수집 844개(real 21 + AI 823)가 213개(real 15 + AI 198)로 정제되었다. 사용 시에는 real 쪽으로 바이어스를 두어 real 65% : AI 35%의 비율로 혼합한다(SYNTH_RATIO=0.35).

추출된 패치는 사용 시 회전 ±15°, 스케일 0.8~1.2, 강도 0.7~1.0, 좌우 반전의 증강(augmentation)을 거쳐 투입되므로, 21개의 씨앗이 수백 가지 변형으로 확장되어 다양성을 확보한다(그림 7).

5.3 screen 블렌딩과 엣지 페더링

합성은 불투명 붙여넣기가 아닌 screen 방식으로 수행한다. 코어 alpha를 1.0까지 포화시켜 실물과 같은 255 흰색 hotspot을 유지하고, 페더링은 패치 전체가 아니라 distance transform으로 구한 가장자리 밴드에만 적용하여 코어의 샤프함을 보존한다.

5.4 기하 정합과 base 레이어

패치는 well 크기에 맞춰 스케일(업스케일 상한 MAX_UPSCALE=2.2 — 과업스케일에 의한 뭉개짐 방지)하고, 조명 방향 회전(±14°)과 경미한 퍼스펙티브 지터를 적용한 뒤 well 폴리곤 내부로 컨테인한다. 반사 합성 전에는 은은한 내부 그라데이션과 얇은 meniscus(액면) 림을 screen으로 깔아 "액체가 채워진" 질감을 부여한다.

5.5 결함 강도 레벨과 GT 라벨

결함 강도는 L1(very mild)~L5(extreme)의 5단계로, streak 개수·크기·밝기·meniscus 강도에 수치 매핑된다. 반사 개수는 전체 절대값이 아닌 well당 밀도로 정의하여 레벨 간 구분이 유지되도록 하였다. 합성 위치를 시스템이 알고 있으므로 GT bbox는 수작업 없이 자동 생성되며, 이미지별 JSON에 {level, seed, synth_version, annotations:[{cartridge, well, bbox, intensity}]}로 기록된다.

6. 결과

  • 정상 사진 1장으로부터 1,000장 이상의 학습 이미지 배치 생성 (레벨 분포 예: L1 50 / L2 200 / L3 500 / L4 200 / L5 50)
  • GT bbox 라벨 100% 자동 생성 — 라벨링 수작업 0
  • 패치 라이브러리 844 → 213 정제 (모양 필터로 비실물형 차단)
  • 결함 강도 5단계 수치 제어, 미리보기 = 실제 출력 (동일 엔진 경유)
  • 출력·마스크의 문서 폴더 영속화 — 재빌드·재실행에도 결과 보존, 배치 태그로 누적 관리
  • 엔진 버전 레지스트리 — 빌드별 엔진 고정(lock) 및 버전 간 비교 가능

7. 한계 및 향후 과제

본 시스템의 합성 품질은 육안 대조 기준으로 개선되어 왔으며, 다음 항목이 열려 있다. 이는 은폐할 결함이 아니라 다음 단계의 정의이다.

  • 사실성의 정량 지표 부재 — 현재는 육안 비교. 실측 대비 분포·밝기 통계 또는 판별기(domain gap) 지표 도입 필요
  • 검출 모델 성능 검증 미완 — 합성 데이터로 학습한 모델이 실물 결함을 얼마나 검출하는지가 최종 증명
  • 레벨 정의의 근거 — L1~L5 강도가 경험값. 실제 결함 심각도와의 매핑 기준 마련 필요
  • streak형 real 패치 부족 — 필터 통과 real 패치가 15개. 추출 소스 확대 또는 AI 생성 조건 개선 여지
  • 물리 근사 — meniscus·그라데이션은 절차적 근사로, 광학·조명 모델 기반 보강 여지

8. 결론

본 개발은 결함 데이터 부족이라는 제약을, 결함 이미지를 자동 양산하는 프로그램의 구현으로 전환한 사례이다. 파라메트릭 기하 정합·재료 검증·빛 기반 블렌딩의 세 요소로 사실성을 확보했고, 위치 기반 GT 자동 생성으로 라벨링 비용을 제거했다. 양산된 데이터는 장비 머신비전의 학습에 투입되어 오인식 재발을 방지하는 최적화 재료가 된다. 합성 품질을 "완성"이 아니라 레퍼런스에 수렴시켜 가는 과제로 정의한 것은, 향후 검출 모델 학습 성능 검증(7장)과 함께 본 시스템의 다음 단계를 이루는 관점이다.

본 보고서는 사내 프로젝트의 기술 기록이며, 제품·공정 관련 세부 정보는 일반화하여 기술하였다.
